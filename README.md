# 好友助手

Delta Chat 私聊中的 Webxdc 联系人助手。当前后端为 **Bun 1.2.23 + TypeScript + 官方 Delta Chat JSON-RPC SDK 2.59.0 + Hono + SQLite WAL**。Webxdc 原有 HTML、CSS、页面和弹窗保留；旧 Python 实现已归档在 `legacy_python_backup/`，不参与运行。

## 功能

- 通过随机加入码加入多个独立网络，切换和退出网络；各网络有独立昵称与隐私设置。
- 查看同网络主动公开的成员，按授权交换 Delta Chat 原生名片；目录不包含联系方式。
- 支持关闭自动交换、双方确认申请、撤销、拒绝、屏蔽、举报、资料修改及二次确认删除数据。
- 小程序管理员密钥验证绑定账号；网页后台与小程序共用同一服务、数据库和管理规则。
- 创建／改名／停用网络、加入码管理、管理员任免、移除成员、举报处理、账号恢复审核与操作记录。封禁功能维持停用。
- Iroh 实时回执与持久化状态更新共用请求编号。每个操作保留持久化副本，避免手机掉线时丢失操作；不自动生成新编号重试。
- 冷通道按版本下发顶层字段增量，数组以当前查询结果整体替换；首次打开、主动刷新和周期检查点发送完整快照，避免删除项残留。数据包通过实例密钥认证，身份来自 Core 的加密私聊与联系人公钥。

## 全新 Linux 服务器安装

需要 Docker Engine、Compose v2、Git、curl 或 wget，支持 x86_64 和 ARM64。使用当前迁移分支：

```sh
git clone --branch fix/webxdc-reliability-20261028 --single-branch https://github.com/cxze299/delta-contact-network-bot.git
cd delta-contact-network-bot
sh install.sh
```

安装程序拒绝覆盖已有凭据、账号和数据库；按提示填写支持 `dcaccount:` 注册的中继、管理员配置、端口及数据目录。它下载并校验 RPC Server 2.59.0，生成独立业务密钥、网页密码、小程序管理密钥与备份密码，通过官方 Core 创建账号，再启动服务。中继可能要求邀请或不开放注册，失败时必须按错误修复，不能删除账号目录重来。

凭据与机器人添加链接保存在 `admin-web-access.txt`，权限 `0600`；`.env` 同样需要保密。网页默认只监听 `127.0.0.1:8787`，公网访问应使用 HTTPS 反向代理。小程序通信不依赖网页端口。

## 使用

1. 添加机器人，完成加密连接并发送任意消息，打开新收到的小程序。
2. 管理员在“我的 → 管理网络”输入小程序管理员密钥，创建网络并向成员提供加入码。普通用户和管理员添加网络都需输入加入码。
3. 成员填写昵称并确认使用当前账号后加入。通过“我的 → 我的网络”添加、切换或退出网络。
4. 在好友列表点击“交换名片”。自动交换需要双方已授权；否则在申请页完成确认。名片出现在与机器人的聊天中，双方自行添加并核验。

界面提示显示 3 秒；超时只表示结果暂未确认，不会自动重发。迟到回执与持久化结果会自动核对。旧消息中的 `.xdc` 是独立版本，不会原地升级；更新后需打开新收到的小程序。

网页后台使用 `admin` 和网页密码。小程序密钥与网页密码相互独立。网络管理员网页账号可由系统管理员签发，权限随网络角色变化。

## 开发和验证

```sh
bun install --frozen-lockfile
bun run typecheck
bun test
bun run pack
```

`webxdc/ui.js` 保留原 DOM 渲染，`transport.js` 实现认证、双通道和增量合并；`scripts/build-ui.ts` 合并生成 `webxdc/app.js`。包输出到 `dist/好友助手.xdc`，无服务令牌的通用包会引导用户向机器人获取绑定版本。机器人按聊天生成专属包。

真实 Core 联调脚本为 `scripts/e2e-core.ts`，仅对独立测试目录运行，不能指向线上账号目录；它需要注册三个测试账号，验证加密小程序送达、真实状态指令、原生名片、重复投递与认证实时回执。浏览器预览可执行 `bun scripts/preview.ts`，该预览用测试身份和数据库，不替代真机验证。

## 更新、状态和停止

```sh
git pull --ff-only
sh scripts/deploy-server.sh
docker compose ps
docker compose logs --tail=50 contact-bot
curl -fsS http://127.0.0.1:8787/api/health
docker compose stop
```

运行时通过 Docker 自动重启；Core 异常退出会使容器退出，由 Docker 启动新进程，恢复持久化游标与处理结果。停止时排空当前任务、停止 Core、执行 WAL checkpoint。容器 `stop_grace_period` 为 15 秒。

## 备份与恢复

`.env` 中设置独立的 `CONTACTBOT_BACKUP_PASSWORD`。启动后自动执行一次在线数据库备份，之后每 24 小时执行一次；保留最长 30 天。手动执行：

```sh
docker compose exec -T contact-bot sh scripts/backup_db.sh
```

备份在独立 SQLite 读取事务中取得一致的在线数据库快照，再通过 PBKDF2 和 AES-256-GCM 加密，直接输出密文。加密文件位于数据卷的 `backups/`。请把备份及独立保存的密码复制到另一台设备。

完整恢复还需要 `.env` 和整个 Core 账号目录。取得一致的完整快照时先 `docker compose stop`，备份这些目录并加密保存，再 `docker compose up -d`；不得同时在两台服务器启动同一个机器人账号。

恢复数据库前停止服务，保存当前数据，再用 `scripts/backup-crypto.ts decrypt` 在隔离目录解密核验，将数据库恢复到配置路径。**保留当前数据目录中的 `deletions.jsonl`**：服务启动时会重新应用备份之后发生的删除。这个独立删除账本只保存不可逆账号标识与时间，不应被旧数据库覆盖。如果账本也丢失，不能保证自动重放备份之后的删除。

名片发出后发生异常时，交付进入待核查状态。系统根据唯一附件文件名核对 Core 已发送记录，不能确认时不会再发；管理员可在检查聊天后结束该交换。

## 隐私与限制

机器人服务端能够处理发送给它的数据。目录不显示地址、公钥或在线状态；名片交付后无法从接收方设备撤回。申请结束 30 天后清理理由及联系方式快照，举报保留 90 天并仅向授权管理员开放。

实时通道是否连通、实际送达时间取决于客户端、中继和网络；类型检查与浏览器测试不等于 iOS 真机验证。所有命令均有持久化通信保障，不承诺端到端始终毫秒级。

目前是单机部署，网页后台和机器人共享一个事件循环与 SQLite 连接。适合约 150 人的网络，不提供多机并行写入或高可用切换。
