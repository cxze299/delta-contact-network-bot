# Delta Chat 联系人网络机器人

这是一个面向约 150 人的小型联系人网络机器人。成员和管理员的日常操作均在与机器人私聊中完成。成员用共享加入码进入网络；选择查找结果后，机器人通过 Delta Chat Core 自动生成并发送申请人的联系人名片。

## 已实现功能

- 多联系网络、管理员自定义任意非空加入码、错误加入限流
- 新成员通过连续问答和中文文字选项完成加入、查找、申请与同意
- 所有引导步骤均可输入 `q` 退出；不再发送或处理 Webxdc 小应用
- 每个网络独立的成员编号、资料和隐私设置
- 昵称默认可查找；搜索结果按数字编号选择，联系人名片随即定向发送
- 申请过期、拒绝、撤销、屏蔽、举报、退出及删除资料
- 普通成员、网络管理员、系统管理员三级权限
- 管理员通过私聊管理网络、加入码、成员、封禁、举报和角色
- 换号后用原成员编号提交恢复申请；管理员核实批准后自动补发有效历史好友名片
- SQLite 事务、重复消息去重、持久化 outbox 和管理审计
- 群聊不响应业务指令；敏感管理输出要求加密私聊

## 本地安装

生产环境建议使用 Python 3.11 或 3.12，以及与 `deltachat2` 版本匹配的 `deltachat-rpc-server` 可执行文件。

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -e .
cp .env.example .env
```

编辑 `.env`，生成至少 32 字节的随机 `CONTACTBOT_SECRET`，并设置系统管理员的 Delta Chat 地址。系统管理员只有在私聊机器人后才会写入数据库；不存在“首位使用者自动成为管理员”的行为。

加载环境变量并初始化：

```bash
set -a
. ./.env
set +a
contactbot init-db
contactbot configure 'dcaccount:example.org'
contactbot run
```

`configure` 参数必须来自可信的 Delta Chat 账号配置 QR 内容。不要把该内容写入命令历史；正式部署可临时关闭历史记录或通过仅 root 可读的启动脚本传入。

从旧部署导入已有初始网络码时，可设置 `CONTACTBOT_INITIAL_NETWORK_CODE`，然后运行 `contactbot seed-network --name 联系人网络`。已有 Delta Chat Core 管理员联系人 ID 可通过 `CONTACTBOT_SYSTEM_ADMIN_CONTACT_IDS` 继续绑定，无需重新登记管理员。

## 首次使用

1. 配置中的系统管理员私聊机器人创建网络；机器人会询问网络名称和自定义加入码。
2. 管理员通过可信渠道把加入码交给成员。加入码允许任意非空字符和长度。
3. 成员添加机器人后会收到欢迎消息，依次回复加入码和昵称，不设隐私同意步骤。
4. 成员发送“查找好友”，回复昵称，再回复结果前的数字编号。
5. 机器人通过 Core 自动生成申请人的 `.vcf` 联系人名片并直接发送；接收方点击名片完成添加。

更换 Delta Chat 账号后，新账号发送“恢复账号”并输入原成员编号。由于成员编号会公开展示，机器人不会只凭编号自动迁移身份；对应网络管理员在私聊中核实并批准后，机器人保留原编号和资料，并向新账号重新发送仍在网络内且双方未屏蔽的历史好友名片。

旧版文本指令继续保留，便于管理员维护和已有成员使用。

## 隐私边界

机器人会处理发给它的账号标识和资料。加入码保存用于校验的带密钥摘要，以及用于管理员私聊查看的 AES-GCM 密文。联系人名片在接收方同意后临时生成，发送完成即删除临时文件。业务数据库中的 Delta Chat 身份使用 HMAC 摘要，发送消息所需的本地联系人 ID 和聊天 ID 仍需保存。

联系方式一旦提交给 Delta Chat 发送，就不能保证撤回，也无法从接收方设备删除。`删除我的数据`清理联系人网络业务资料；Delta Chat Core 的历史消息、缓存及备份清理由部署维护流程负责。

## 当前联调状态

自动化测试覆盖核心业务逻辑。真实账号联调仍需提供：一个专用机器人账号、两个测试账号、Linux 上的 RPC Server。联调时必须验证私聊识别、加密标记、地址文本在各目标客户端中的添加体验、发送失败重试和账号恢复。

更多说明见 [部署文档](deploy/DEPLOY.md)、[成员和管理员指南](docs/USER_GUIDE.md) 与 [验收清单](docs/ACCEPTANCE.md)。

## 本地管理后台

`contactbot admin-web` 提供一个可编辑的网页后台。Docker Compose 只把它映射到 NAS 的 `127.0.0.1:8787`，需要通过 SSH 端口转发访问。后台采用独立的 HTTP Basic 管理令牌，用户名固定为 `admin`，并对修改表单执行 CSRF 校验。

后台可编辑网络名称、启停状态、自定义加入码、成员角色、成员状态、目录可见性和接收申请设置。页面不会显示成员联系方式、Delta Chat 地址、账号摘要或加入码原文。

Windows 部署维护机可以运行 `start-admin-web.ps1` 自动建立 SSH 隧道并打开后台。登录信息保存在部署时生成、已加入 `.gitignore` 的 `admin-web-access.txt` 中。
