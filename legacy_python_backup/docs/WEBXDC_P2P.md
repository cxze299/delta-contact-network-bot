# 纯 Webxdc 联系人网络原型

这个 `.xdc` 文件在一个 Delta Chat 群聊中运行。它不连接 NAS，也不向机器人发送日常操作消息；成员点击按钮后使用 `webxdc.sendUpdate()` 直接同步状态。

## 使用方式

1. 管理员先在自己与测试群聊中打开 `联系人网络-点对点.xdc`。
2. 填写网络名称、自定义加入码和管理员昵称。创建完成后，把**同一个文件**发送到网络群聊。
3. 成员在该群聊打开文件，填写加入码、昵称和介绍即可加入。
4. 成员资料、查找、申请、接受、拒绝、撤销和管理员封禁都会直接在应用内同步。

成员应在同一个 Webxdc 实例中操作；不要为每位成员重新发送不同副本，否则会形成彼此不连通的网络。

## 隐私模型

公开资料和申请是否存在会同步到群里的所有成员。联系理由和 Delta Chat 地址不会明文同步：它们使用申请双方登记的 ECDH 公钥在本地加密，只有对应接收者能解密。

地址只保存在用户的本地应用存储，直到该用户同意申请才生成加密信封。管理员无法读取成员之间的已加密地址或理由。

## 当前原型边界

- 网络加入码只在客户端通过 SHA-256 哈希验证，没有服务器限流。必须设置较长、难猜的自定义加入码。
- 首次创建网络的更新是信任根。管理员创建后应立即在群中核对网络名称和管理员身份，再邀请成员。
- 管理员密钥、成员密钥和本地地址存于该设备的小应用存储。清理 Webxdc 数据或更换设备会丢失私钥与已解密地址，当前没有恢复流程。
- 所有成员持有更新历史。退出或删除只停止后续显示，不能抹除他人设备已有历史。已加密的内容仍无法由其他成员解密。
- 网络、成员资料和申请通过 Webxdc 更新历史持久保存，关闭后会从历史重建；本地私钥和个人地址使用 `localStorage`。官方说明本地存储可能被客户端在长期未使用后回收，因此当前版本只保证正常关闭再打开，不保证清除应用数据后的恢复。
- 这是可运行的原型，尚未完成真实多设备客户端互通、密钥备份、密钥轮换、管理员交接和举报加密流程的验收。

## 真实联调记录

2026-09-13 使用本机 Delta Chat Core 2.59.0 和两个已配置账号完成以下检查：

- `.xdc` 文件通过真实加密邮件链路送达另一个账号；
- 两个账号分别发送的 Webxdc 状态更新均被对方读取；
- 停止并重新启动 Core 后，双方仍能从 Webxdc 更新历史读取之前的状态。

联调同时修复了首次 `join` 更新在重新打开时因成员公钥尚未登记而被拒绝的问题。修复后首次加入更新直接使用该更新携带的成员公钥验签，后续更新才使用已登记公钥。
